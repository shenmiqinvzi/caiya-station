## 3. 原生接口与关键事实

本轮用只读程序集核查确认：

- `PlayerStorage.Push(Item, bool toBufferDirectly)` 在 `toBufferDirectly=true` 时跳过仓库，直接 `ItemTreeData.FromItem` → `IncomingItemBuffer` → `Detach` → `DestroyTree`。不需要自建物品序列化。
- `PlayerStorage.IncomingItemBuffer` 实际来自 `PlayerStorageBuffer.Buffer`；静态列表在类型初始化时创建，因此在 raid 中可用。
- `EconomyManager.Pay(Cost, bool, bool)` 同时支持账户金钱与现金；`Cost` 构造为 `(long money, (int id,long amount)[] items)`。
- 玩家携带背包为 `CharacterMainControl.CharacterItem.Inventory`（容量由背包槽决定）；`CharacterMainControl.Main` 是当前角色。
- `Item.Value / StackCount / TotalWeight / Tags / TypeID / CanDrop`；`ItemTreeExtensions.DestroyTree` 用于丢失销毁。
- 物品表从 `resources.assets` 只读解析：**368 = 虚化的羽毛，890 = 狗牌，451 = 现金**；保护标签实际为 `Quest / Key / SpecialKey / Cash / Continer / Backpack`（`Continer` 是游戏内拼写）。
- `LevelManager.IsRaidMap / IsBaseLevel / LevelInited`、`MultiSceneCore.MainScene / MainSceneID` 用于场景与 raid 判定。
- `SimplePointOfInterest.Create(position, sceneID, name, sprite, hideIcon)` 用于地图标记；`Saves.SavesSystem.Save/Load/KeyExisits/SaveFile` 用于三个存档键。

## 3.1 视觉与交互打磨

这一轮把“能看”提升到“愿意看”，全部由运行时生成的 UI 主题和 Unity 基础几何体完成，不新增外部资源依赖：

- **统一主题**：深绿黑底、荧光绿强调色、运行时生成的圆角 9-slice 纹理（面板/卡片/按钮/胶囊），按钮有普通/悬停/按下状态，禁用按钮换用暗色底。
- **面板结构**：左侧背包清单（物品图标、品质色条、勾选框、整行点击、悬停详情）+ 右侧决策区（货值/运费/损耗/护送费/预计总成本、送达-丢失比例条、三张护送卡、不可确认原因）+ 底部固定余额与操作按钮。
- **信息密度**：单件价值、总价值、重量分列；物品名过长时悬停查看完整名称/描述/不可寄原因；不可寄物品整行变灰而不是消失。
- **回执**：结构化信息块与左右两栏清单，“已送达/全部丢失”徽标；比纯文本更适合截图查账。
- **世界提示**：80 米内胶囊距离标签；在身后/画面外时屏幕边缘显示方向箭头；公告与发货提示使用顶部淡入淡出胶囊，同时保留原生提示。
- **驿站模型**：加高柜台、招牌框、屋顶饰条、鸭头、吊灯、旗帜。开门时旗帜轻摆、吊灯呼吸、鸭头缓慢左右看；发货后招牌/旗帜变灰、吊灯熄灭、卷帘落下。
- **面板输入保护**：面板是 IMGUI 覆盖层，不会自动阻止游戏输入。用随包 Harmony 2.4.1 与独立 ID `CaiYaStation.PanelInput`，在面板打开时拦截攻击、使用、拾取、丢弃、冲刺/瞄准、交互与枪械入口；关闭/停用/UI 异常时解除。移动不锁定，走远 6 米自动关闭。`Safety.RequireInputGuard=true` 时，补丁不可用会拒绝打开面板并提示原因。
- **二次确认**：货值达到 `Safety.ConfirmAboveValue`（默认 10000）或单件寄送（`ConfirmWhenSingleStack`）时，先进入确认页，显示货值、预计损耗、实际扣除、预计总成本与风险提示，再次确认才扣费。
- **诊断面板**：与主面板同一主题，显示契约、地图、token、背包、缓冲区、输入拦截状态、最近回执与日志路径。

静态设计预览见《界面预览-0.1.0.md》；它不是游戏截图，实机受字体、分辨率与材质影响。

## 4. 发货事务

顺序（与设计 §12.3 对齐）：

1. 重新读取背包，校验物品仍在、可寄、12 格/25kg、站点未用、当前地图一致、缓冲区可用、金钱/现金/护送物品足够。
2. 计算报价与损耗计划；生成 `ShipmentId`，写 `Prepared` 日志并立即保存。
3. `EconomyManager.Pay` 一次支付运费 + 护送费/物品；失败则回执 Aborted，不移动物品、不消耗站点。
4. 写 `Paid`，同时把站点标记 `Used` 并保存（钱已扣，崩溃也不能让站点重新开业）。
5. 逐件：丢失 → 从背包移除并 `DestroyTree`；幸存 → `PlayerStorage.Push(..., true)`（原生负责 detach/入缓冲区）。日志记录 `Lost/Pushed`。
6. 写 `Completed`、回执，保存并 `SaveFile(false)`。
7. 任一步抛异常 → `Interrupted`，保存；启动/读档后 `RecoverPending` 只推送仍在背包的幸存物品，不重复扣费、不重复推送。

原则：**永不复制、永不静默销毁**；丢失物品进回执；已推送的实例不会再次推送。

## 5. 配置

`mod/config.json`：

- `Limits`：12 格 / 25kg。
- `Pricing`：0.10 / 200 / 5000。
- `Loss`：四档、20% 封顶、30% 件数、50% 价值、至少保留 1 个堆叠。
- `Escorts`：拾荒者 1000 + 368×4、×0.6；雇佣兵 2000 + 890×4、×0.3；下限 2%。
- `Protection`：保护标签、容器标签、货币标签、名称前缀、TypeID。
- `Placement`：寻位间距/撤离点距离/传送点距离/坡度/搜索环。
- `Ui`：面板尺寸、标签距离、世界标签开关、`UnlockCursor`（打开面板时显示并解锁光标，关闭恢复，默认 true）。
- `Safety`：`RequireInputGuard`（拦截失败是否禁止开面板，默认 true）、`ConfirmAboveValue`（货值达到多少二次确认，默认 10000）、`ConfirmWhenSingleStack`（单件寄送是否二次确认，默认 true）。
- `Keys.Diagnostics`：默认 F8。

`mod/station-layout.json`：两张地图、每图 10 个候选锚点、每局 1/2 个。锚点来自本机只读地图元数据（入口、路口、StartPoint、TeleportMarker 等），不是宣称已实走勘察的最终落点；运行时仍会做安全地面与约束校验。

JSON 反序列化使用 `ObjectCreationHandling.Replace`，避免 `Loss.Bands` 等带默认值的列表被追加成双份（本轮测试发现并修复）。

## 7. 游戏内验收清单（按顺序）

前置：完全退出游戏 → 备份存档 → 安装 → 重启 → 模组菜单启用“菜鸭驿站”。

1. **加载**：进入任意存档，F8 面板显示“原生契约：通过”，日志无 `Native contract FAILED`。
2. **仓库区站点**：进入仓库区，地图有绿色“菜鸭驿站”标记；靠近后屏幕标签显示距离；按交互键打开面板。
3. **单件闭环**：选 1 件低价值背包物品，付 200 运费发货；物品从背包消失；面板显示回执；回地堡马蜂自提点能领取。
4. **读档不复制**：发货后读档/重进游戏，背包和缓冲区数量正确；驿站仍是已停业。
5. **死亡**：发货后死亡，回地堡自提点仍能领取已送达物品。
6. **农场镇两站**：进入农场镇，地图有 2 个驿站；用掉一个后另一个仍可用；同一 raid 离开再回来位置不重 roll。
7. **上限/保护**：尝试 13 格或 >25kg 应禁止确认；任务/钥匙/现金/容器不可选；护送物品不足时选项置灰并给出原因。
8. **损耗/护送**：选 2 件以上发货，回执的丢失件数 ≤30%、价值 ≤50%；请拾荒者/雇佣兵后损耗率分别为 ×0.6/×0.3（下限 2%）。
9. **异常**：金钱/现金不足、缓冲区不可用、重复点击确认，均不应扣费或移动物品。
10. **兼容**：在用户现有模组列表下重复 2–6；若崩溃，附日志与 F8 面板。
11. **安全路径**：货值 ≥10000 或单件寄送时出现二次确认页；“返回修改”不扣费，确认后才扣费；F8 输入拦截不可用且 `RequireInputGuard=true` 时，驿站面板拒绝打开并提示原因。

记录建议：地图 → 操作 → 预期 → 实际现象；附 `logs\caiyastation.log` 末尾与 F8 截图。

## 8. 已知限制与待确认

- **Phase 0 未在运行中的游戏里跑过**：本轮是静态接口核对 + 离线测试；驿站寻位、交互、面板输入都需要首轮实机确认。
- **Harmony 输入拦截未实机验证**：目标方法已核对，但补丁是否在游戏 Mono 下成功应用、是否与其它模组冲突，需要进游戏看 F8 的“输入拦截：开启（面板打开时）”并实际点击面板确认不误开枪。若补丁失败且 `Safety.RequireInputGuard=true`，面板会拒绝打开并提示，需查看日志中的 `NativePatches` 错误。
- **面板鼠标**：默认 `Ui.UnlockCursor=true`，打开面板时保存原光标状态并强制显示/解锁，关闭恢复。若实机仍无法点击，需要改原生 UI 输入层或检查游戏是否每帧重新锁定光标。
- **撤离点距离**：优先 40–80m；若地图中找不到同时满足的点，会放宽到 ≥40m 或忽略该约束，并在日志写明。最终落点需要按实景调锚点。
- **护送物品扣除来源**：预检只统计背包；原生 `Cost` 可能从仓库/宠物库存扣同类物品（若背包数量足够，携带条件仍成立）。不会出现“没带也能请”的情况。
- **崩溃窗口**：支付成功与 `Paid` 落盘之间若进程崩溃，重启会丢弃 `Prepared` 日志（不重复扣费、物品仍在背包，但已扣的钱不会自动退回）。这是当前写前日志能保证的上限，需要后续用更细的支付回执消除。
- **回执历史**：只写存档，没有基地查看界面；设计 §18 的“基地说明终端/回执终端”未做。
- **容器**：第一版不寄容器，也不展开容器内容。
- **旧模组**：`DuckovSharedBike` 仍在 Mods 目录；两者可同时安装，但建议只启用“菜鸭驿站”，避免旧模组对背包/经济/传送的 patch 干扰验收。
- **美术**：亭子/鸭头为程序化占位，后续可换成正式模型与招牌。
- **多地图 raid**：存档按 `RaidToken` + 地图保存站点；同一 raid 跨主地图会分别生成并保留。实机跨图路径尚未验证。

## 10. 2026-10-22 首轮试玩热修

首轮试玩日志显示驿站已规划、模型已创建，但地图上没有标记、现场也难找到。根因是 `StationWorld.SyncScene` 用 `MultiSceneCore.MainScene`（`Level_Farm_Main`）作为实体场景和 POI 的 `sceneID`；玩家实际所在、地图正在过滤的是 `ActiveSubScene`（`Level_Farm_01`）。修复内容：

- 场景选择改为优先 `MultiSceneCore.ActiveSubScene`，`MainScene` 仅作回退；日志追加 `activeSubScene=`。
- `SimplePointOfInterest.Create` 的 `sceneID` 改用 `MultiSceneCore.ActiveSubSceneID`，并用 `Setup` 重新注册，确保地图按当前子场景过滤。
- 旧存档里 `SceneName` 为 `MainScene.name` 的站点记录自动迁移到当前子场景，避免修复后仍无法交互。
- `ClearOfExtraction` 改为按**最近撤离点**判定 40–80m；旧实现要求同时满足每个撤离点，多撤离点地图上必然降级。
- F8 诊断新增“最近驿站：距离/坐标/营业状态”。
- `NativeContract` 增加 `ActiveSubSceneID` 成员检查，探针从 59 项增至 60 项。

仍待复测：地图标记是否可见、实体是否渲染、交互/面板是否可用、发货与领取闭环。

- **地图标记**：图标从 32px 提升到 64px 抗锯齿鸭头徽章，颜色/停业灰化不变。
- **进图提示**：不再只是一个顶部胶囊，而是带鸭头图标、标题、正文、提示语、右侧标签的横幅；从顶部滑入、淡出，支持最多 4 条队列，进图公告/基地说明/发货完成/错误共用一套样式。世界标签关闭时横幅仍然显示。
- 已知风险：`TextMesh` 的朝向按 Unity 默认（文字可读面朝 -Z）旋转 180° 面向 +Z；若实机出现镜像/背面，需要翻转招牌文字的 `localRotation`。动态字体在无中文字体的系统上会退化，招牌仍有颜色与鸭头徽记。

## 12. 2026-10-22 可玩性审查补强

针对“地图有标识、现场有实体、能正常交互”做了一轮代码审查，补了以下路径：

- **标记失败重试**：实体创建成功但 `SimplePointOfInterest` 创建/注册失败时，下一 tick 会重新建标记；重建前会销毁同 ID 的旧标记，避免重复 POI。
- **实体自检**：`CreateStationObject` 检查渲染器数量；为 0 时销毁并重试，避免“记录存在但看不见”。
- **补足站点数量**：不再只在 `existing.Count == 0` 时规划；农场镇少于 2 个时会排除已有锚点、补足剩余数量，失败每 10 秒重试。
- **F8 站点状态**：新增“实体 N / 标记 M / 营业 K（本图共 T）”，可直接确认地图标记与实体是否都创建。
- **面板打开日志**：`Opening station panel id=... distance=...` 与 `Shipment panel opened station=... rows=...`，便于区分“没走到交互范围”和“面板没打开”。
- **恢复事务**：跨进程恢复增加 `TypeId + StackCount + UnitValue` 一对一指纹匹配；仍找不到的件不再伪报“已送达”，而是保留 `Interrupted` 记录并提示；正常发货中找不到的物品改记丢失，回执保持诚实。

仍待实机确认：地图标记是否实际绘制、实体是否可见、交互键能否打开面板、发货/领取闭环。代码层已覆盖失败重试与诊断，但**没有替代一次进游戏验证**。
