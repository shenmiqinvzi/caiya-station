## 3. 原生接口与关键事实

本轮用只读程序集核查确认：

- `PlayerStorage.Push(Item, bool toBufferDirectly)` 在 `toBufferDirectly=true` 时跳过仓库，直接 `ItemTreeData.FromItem` → `IncomingItemBuffer` → `Detach` → `DestroyTree`。不需要自建物品序列化。
- `PlayerStorage.IncomingItemBuffer` 实际来自 `PlayerStorageBuffer.Buffer`；静态列表在类型初始化时创建，因此在 raid 中可用。
- `EconomyManager.Pay(Cost, bool, bool)` 同时支持账户金钱与现金；`Cost` 构造为 `(long money, (int id,long amount)[] items)`。
- 玩家携带背包为 `CharacterMainControl.CharacterItem.Inventory`（容量由背包槽决定）；`CharacterMainControl.Main` 是当前角色。
- `Item.Value / StackCount / TotalWeight / Tags / TypeID / CanDrop`；`ItemTreeExtensions.DestroyTree` 用于丢失销毁。
- 物品表从 `resources.assets` 只读解析：**368 = 虚化的羽毛，890 = 狗牌，451 = 现金**；保护标签实际为 `Quest / Key / SpecialKey / Cash / Continer / Backpack`（`Continer` 是游戏内拼写）。
- `LevelManager.IsRaidMap / IsBaseLevel / LevelInited`、`MultiSceneCore.MainScene / MainSceneID` 用于场景与 raid 判定。
- `SimplePointOfInterest.Create(position, sceneID, name, sprite, hideIcon)` 用于地图标记；`Saves.SavesSystem.Save/Load/KeyExisits/SaveFile` 用于三个存档键。

## 3.1 视觉与交互打磨

这一轮把“能看”提升到“愿意看”，全部由运行时生成的 UI 主题和 Unity 基础几何体完成，不新增外部资源依赖：

- **统一主题**：深绿黑底、荧光绿强调色、运行时生成的圆角 9-slice 纹理（面板/卡片/按钮/胶囊），按钮有普通/悬停/按下状态，禁用按钮换用暗色底。
- **面板结构**：左侧背包清单（物品图标、品质色条、勾选框、整行点击、悬停详情）+ 右侧决策区（货值/运费/损耗/护送费/预计总成本、送达-丢失比例条、三张护送卡、不可确认原因）+ 底部固定余额与操作按钮。
- **信息密度**：单件价值、总价值、重量分列；物品名过长时悬停查看完整名称/描述/不可寄原因；不可寄物品整行变灰而不是消失。
- **回执**：结构化信息块与左右两栏清单，“已送达/全部丢失”徽标；比纯文本更适合截图查账。
- **世界提示**：80 米内胶囊距离标签；在身后/画面外时屏幕边缘显示方向箭头；公告与发货提示使用顶部淡入淡出胶囊，同时保留原生提示。
- **驿站模型**：加高柜台、招牌框、屋顶饰条、鸭头、吊灯、旗帜。开门时旗帜轻摆、吊灯呼吸、鸭头缓慢左右看；发货后招牌/旗帜变灰、吊灯熄灭、卷帘落下。
- **面板输入保护**：面板是 IMGUI 覆盖层，不会自动阻止游戏输入。用随包 Harmony 2.4.1 与独立 ID `CaiYaStation.PanelInput`，在面板打开时拦截攻击、使用、拾取、丢弃、冲刺/瞄准、交互与枪械入口；关闭/停用/UI 异常时解除。移动不锁定，走远 6 米自动关闭。`Safety.RequireInputGuard=true` 时，补丁不可用会拒绝打开面板并提示原因。
- **二次确认**：货值达到 `Safety.ConfirmAboveValue`（默认 10000）或单件寄送（`ConfirmWhenSingleStack`）时，先进入确认页，显示货值、预计损耗、实际扣除、预计总成本与风险提示，再次确认才扣费。
- **诊断面板**：与主面板同一主题，显示契约、地图、token、背包、缓冲区、输入拦截状态、最近回执与日志路径。

静态设计预览见《界面预览-0.1.0.md》；它不是游戏截图，实机受字体、分辨率与材质影响。

## 4. 发货事务

顺序（与设计 §12.3 对齐）：

1. 重新读取背包，校验物品仍在、可寄、12 格/25kg、站点未用、当前地图一致、缓冲区可用、金钱/现金/护送物品足够。
2. 计算报价与损耗计划；生成 `ShipmentId`，写 `Prepared` 日志并立即保存。
3. `EconomyManager.Pay` 一次支付运费 + 护送费/物品；失败则回执 Aborted，不移动物品、不消耗站点。
4. 写 `Paid`，同时把站点标记 `Used` 并保存（钱已扣，崩溃也不能让站点重新开业）。
5. 逐件：丢失 → 从背包移除并 `DestroyTree`；幸存 → `PlayerStorage.Push(..., true)`（原生负责 detach/入缓冲区）。日志记录 `Lost/Pushed`。
6. 写 `Completed`、回执，保存并 `SaveFile(false)`。
7. 任一步抛异常 → `Interrupted`，保存；启动/读档后 `RecoverPending` 只推送仍在背包的幸存物品，不重复扣费、不重复推送。

原则：**永不复制、永不静默销毁**；丢失物品进回执；已推送的实例不会再次推送。

## 5. 配置

`mod/config.json`：

- `Limits`：12 格 / 25kg。
- `Pricing`：0.10 / 200 / 5000。
- `Loss`：四档、20% 封顶、30% 件数、50% 价值、至少保留 1 个堆叠。
- `Escorts`：拾荒者 1000 + 368×4、×0.6；雇佣兵 2000 + 890×4、×0.3；下限 2%。
- `Protection`：保护标签、容器标签、货币标签、名称前缀、TypeID。
- `Placement`：寻位间距/撤离点距离/传送点距离/坡度/搜索环（默认 `{8,12,16,22,30,40}`，见 §16）。
- `Ui`：面板尺寸、标签距离、世界标签开关、`UnlockCursor`（打开面板时显示并解锁光标，关闭恢复，默认 true）。
- `Safety`：`RequireInputGuard`（拦截失败是否禁止开面板，默认 true）、`ConfirmAboveValue`（货值达到多少二次确认，默认 10000）、`ConfirmWhenSingleStack`（单件寄送是否二次确认，默认 true）。
- `Keys.Diagnostics`：默认 F8。

`mod/station-layout.json`：两张地图、每图 10 个候选锚点、每局 1/2 个。锚点来自本机只读地图元数据（入口、路口、StartPoint、TeleportMarker 等），不是宣称已实走勘察的最终落点；运行时仍会做安全地面与约束校验。

JSON 反序列化使用 `ObjectCreationHandling.Replace`，避免 `Loss.Bands` 等带默认值的列表被追加成双份（本轮测试发现并修复）。

## 7. 游戏内验收清单（按顺序）

前置：完全退出游戏 → 备份存档 → 安装 → 重启 → 模组菜单启用“菜鸭驿站”。

1. **加载**：进入任意存档，F8 面板显示“原生契约：通过”，日志无 `Native contract FAILED`。
2. **仓库区站点**：进入仓库区，地图有绿色“菜鸭驿站”标记；靠近后屏幕标签显示距离；按交互键打开面板。
3. **单件闭环**：选 1 件低价值背包物品，付 200 运费发货；物品从背包消失；面板关闭并弹「发货完成」；回地堡马蜂自提点能领取，且回地堡时自动弹出该次回执。
4. **读档不复制**：发货后读档/重进游戏，背包和缓冲区数量正确；驿站仍是已停业。
5. **死亡**：发货后死亡，回地堡自提点仍能领取已送达物品。
6. **农场镇两站**：进入农场镇，地图有 2 个驿站；用掉一个后另一个仍可用；同一 raid 离开再回来位置不重 roll。
7. **上限/保护**：尝试 13 格或 >25kg 应禁止确认；任务/钥匙/现金/容器不可选；护送物品不足时选项置灰并给出原因。
8. **损耗/护送**：选 2 件以上发货，回执的丢失件数 ≤30%、价值 ≤50%；请拾荒者/雇佣兵后损耗率分别为 ×0.6/×0.3（下限 2%）。
9. **异常**：金钱/现金不足、缓冲区不可用、重复点击确认，均不应扣费或移动物品。
10. **兼容**：在用户现有模组列表下重复 2–6；若崩溃，附日志与 F8 面板。
11. **安全路径**：货值 ≥10000 或单件寄送时出现二次确认页；“返回修改”不扣费，确认后才扣费；F8 输入拦截不可用且 `RequireInputGuard=true` 时，驿站面板拒绝打开并提示原因。
12. **面板观感/交互**（2026-10-23 新增）：悬停任意背包行，高亮与右侧详情框稳定不闪、不遮住该行；右栏「待运送货物 / 费用与风险 / 护送队」三段无文字重叠；单击选中/取消、清空、全选、滚轮滚动都只作用在各自区域，点空白处不放枪。

记录建议：地图 → 操作 → 预期 → 实际现象；附 `logs\caiyastation.log` 末尾与 F8 截图。

## 8. 已知限制与待确认

- **Phase 0 未在运行中的游戏里跑过**：本轮是静态接口核对 + 离线测试；驿站寻位、交互、面板输入都需要首轮实机确认。
- **Harmony 输入拦截未实机验证**：目标方法已核对，但补丁是否在游戏 Mono 下成功应用、是否与其它模组冲突，需要进游戏看 F8 的“输入拦截：开启（面板打开时）”并实际点击面板确认不误开枪。若补丁失败且 `Safety.RequireInputGuard=true`，面板会拒绝打开并提示，需查看日志中的 `NativePatches` 错误。
- **面板鼠标**：默认 `Ui.UnlockCursor=true`，打开面板时保存原光标状态并强制显示/解锁，关闭恢复。若实机仍无法点击，需要改原生 UI 输入层或检查游戏是否每帧重新锁定光标。
- **撤离点距离**：优先 40–80m；找不到时只放宽上限（≥40m），下限 40m 不再放宽，并在日志写明每一档被拒的原因计数。最终落点仍建议按实景微调锚点（见 §16）。
- **护送物品扣除来源**：预检只统计背包；原生 `Cost` 可能从仓库/宠物库存扣同类物品（若背包数量足够，携带条件仍成立）。不会出现“没带也能请”的情况。
- **崩溃窗口**：支付成功与 `Paid` 落盘之间若进程崩溃，重启会丢弃 `Prepared` 日志（不重复扣费、物品仍在背包，但已扣的钱不会自动退回）。这是当前写前日志能保证的上限，需要后续用更细的支付回执消除。
- **回执历史**：只写存档，没有基地查看界面；设计 §18 的“基地说明终端/回执终端”未做。
- **容器**：第一版不寄容器，也不展开容器内容。
- **旧模组**：`DuckovSharedBike` 仍在 Mods 目录；两者可同时安装，但建议只启用“菜鸭驿站”，避免旧模组对背包/经济/传送的 patch 干扰验收。
- **美术**：亭子/鸭头为程序化占位，后续可换成正式模型与招牌。
- **多地图 raid**：存档按 `RaidToken` + 地图保存站点；同一 raid 跨主地图会分别生成并保留。实机跨图路径尚未验证。

## 10. 2026-10-22 首轮试玩热修

首轮试玩日志显示驿站已规划、模型已创建，但地图上没有标记、现场也难找到。根因是 `StationWorld.SyncScene` 用 `MultiSceneCore.MainScene`（`Level_Farm_Main`）作为实体场景和 POI 的 `sceneID`；玩家实际所在、地图正在过滤的是 `ActiveSubScene`（`Level_Farm_01`）。修复内容：

- 场景选择改为优先 `MultiSceneCore.ActiveSubScene`，`MainScene` 仅作回退；日志追加 `activeSubScene=`。
- `SimplePointOfInterest.Create` 的 `sceneID` 改用 `MultiSceneCore.ActiveSubSceneID`，并用 `Setup` 重新注册，确保地图按当前子场景过滤。
- 旧存档里 `SceneName` 为 `MainScene.name` 的站点记录自动迁移到当前子场景，避免修复后仍无法交互。
- `ClearOfExtraction` 改为按**最近撤离点**判定 40–80m；旧实现要求同时满足每个撤离点，多撤离点地图上必然降级。
- F8 诊断新增“最近驿站：距离/坐标/营业状态”。
- `NativeContract` 增加 `ActiveSubSceneID` 成员检查，探针从 59 项增至 60 项。

## 15. 2026-10-23 体验审计后的修复轮

对整份模组代码做过一轮只读审计，按「会直接弄坏一局游戏 / 会让人以为模组坏了」的优先级排下来，本轮先修 A 组 6 条与 B 组若干条。审计出的其余项（B7/B12/B13）经复核对代码后不改，理由写在 15.3。

### 15.1 会伤到玩家的一类（A 组）

- **A1 一次异常就永久废掉整个界面**：`ModBehaviour.OnGUI` 的 catch 以前直接把 `_uiFailed = true`，此后世界标签、主面板、F8 诊断全部不再绘制，只能重启游戏，且屏幕上看不到任何提示。现在单帧异常只记录并停 1–8 秒后重试（退避 = `min(1 + 次数, 8)`），连续 5 次才真正停用，日志逐次写 `UI frame failed (n/5)`，停用那一条写明「需要重新加载存档/游戏」。
- **A2 恢复发货时可能钱货两空**：崩溃恢复靠 `InstanceId` 找件，找不到再用 `TypeID + StackCount + UnitValue` 全等匹配；玩家在崩溃后拆过堆、合并过堆就永远匹配不上，件既不会进自提点，pending 记录也会永久留着，每次进游戏都弹一次「仍有 N 件未能确认送达」。现在按四级退让匹配（精确 → 同型同值 → 同型任意值），并对超过 `RecoveryExpiryDays = 7` 天仍未解析的记录按丢失结算收尾——回执照常生成、劫掠者也照常点名，pending 不再无限积压。
- **A3 费用卡把规则写死在画面里**：`运费 10%` 与 `上限 30%件 / 50%值` 是硬编码字符串，改 `config.json` 的 `Rate` / `MaxLostStackFraction` / `MaxLostValueFraction` 后，界面数字照着新规则算，旁边说明还是旧规则。改为 `ShipmentView.FeeRateText` / `LossCapText`，由 `BuildView` 用配置现算（预览器不填就走默认值）。
- **A4 提示永不消失**：`_hint` 以前只在做下一个操作时被覆盖，点一次灰物品，页脚红字能挂一整局。现在 `ShowHint()` 统一写入并记 `_hintUntil = Time.unscaledTime + 3.5f`，`BuildView` 到期自动清。
- **A5 回车直接扣费**：以前面板内任何位置按回车都会立刻 `RequestShip()`，手上没选东西也照发。改为 Enter/KeypadEnter 一律走 `RequestShip(true)`，即强制先弹确认单；正常点「确认发货」的路径不变。
- **A6 关掉模组仍能开面板**：`Enabled = false` 以前只让 `Tick` 早退，已生成的站点还能被交互打开。`CanOpen`、`OpenStation`、`DrawWorldLabels` 三处都补了前置判断，关掉后连世界标签都不画，交互时给一句「模组已停用（config.json 里 Enabled 为 false）」。

### 15.2 让人以为模组坏了的一类（B 组）

- **B1 悬浮详情永远压在右栏上**：详情卡以前固定画在左栏右侧 10px，宽度 300，正好整块盖住右栏的护送卡，却又只有视觉、不吃点击。改为贴着当前行：优先画在行下方 8px，放不下画在行上方，都放不下才退回面板内夹住；横向仍限制在左栏内（`rowRect.x + 74` 起，夹在 `Left.x + 10` 与 `Left.xMax - width - 10` 之间）。
- **B2 列头会勾到看不见的行**：命中矩形用的是滚动前的整行矩形，`ListView` 外的行也照样 `AddHit`；列表滚到一半时点列头，会勾上屏幕外的物品。新增 `PanelRenderer.Clip(inner, outer)`，行与清单行的命中矩形都按各自视图裁剪。
- **B3 全选静默截断**：点「全选可寄」撞到 12 格 / 25 kg 时只选一部分，界面不给任何解释。现在用 `truncated` 标记，结束后提示「装不下了：只选了 N 格 / X kg（上限 12 格 / 25 kg）」。
- **B4 已用驿站直接关面板**：站点记录变成已用（存档重载或本局发过）时面板静默 `Close()`，看起来像崩了。现在先弹一条警告通知「这个驿站本局已经发过货了，下一局再来。」再关。
- **B5 非内置地图露出内部 id**：副标题以前只映射仓库区/农场镇，其它地图直接把 `Level_XXX_Main` 显示给玩家。`MapName` 改为方法：内置图用中文名，其余剥掉 `Level_` 前缀与 `_Main` 后缀、下划线换空格，空串回落到「未知区域」。
- **B6 0% 也画成危险色**：丢件率恒用 `Danger` 红，`0%` 时看起来像出事了。改为 `loss > 0.001f ? Danger : TextFaint`。
- **B8 通知硬切**：`DrawNotice` 到点直接 `StartNextNotice()`，淡出分支永远算不到。现在多留 0.45 秒淡出窗口（`NoticeFade`、`_noticeFadeUntil`），`ClearNotices` / `StartNextNotice` 复位。
- **B9 世界标签串场景**：同一个 map 下的站点以前不分场景全画，仓库子场景与 raid 变体会互相把标签画到奇怪的位置。现在按 `SceneName` 过滤；外层 catch 也不再空吞，10 秒节流写一次 `World label draw failed: …`。
- **B10 换存档把未读回执吃掉**：`ResetForSave()` 直接 `_panel?.Close()`，若此时正开着未读回执，会触发 `ReceiptClosed` 把它标成已读。改为先 `DismissReceipt()`（静默收起、不算已读）再 `Close()`，同时把 `_lastReceiptCountNotified` 复位成 -1。
- **B11 「第一版不寄送」**：面向玩家的文案带工程口吻，改成「容器类物品不可寄送」，代码两条、测试两条同步。

### 15.3 复核后不改的项

- **B7 第三张护送卡切边**：复算卡 3 的底边是 166，护送带高 168，没有越界；`PanelPreview.CheckLayouts` 本身就断言了每张卡都在 `Escort` 带内。属于看预览图时的误判，`EscortHeight` 顺手改成由 `EscortCardCount` 推导，避免以后加卡再对不上。
- **B12 最低运费 200 的性价比**：低价单运费占比高是刻意的设计杠杆（逼玩家凑单），提示里已有「运费高于货值」的警告，不再加百分比噪声。
- **B13 面板打开时挡住交互键**：这是刻意的输入守卫，Esc 与右上角 × 都能退出，不给交互键开口子。

### 15.4 验收（追加第 14 项）

14. **审计修复轮**：把 `config.json` 的 `Pricing.Rate` 改成 0.2，费用卡必须显示「运费 20%」；点灰物品/撞上限的页脚提示 3–4 秒后自己消失；面板内连按回车只弹确认单、不直接发货；关掉 `Enabled` 后站点不可交互也不再画标签；左栏滚到底时点列头不会勾中不可见的行；悬停详情不再覆盖右栏且能跟着行上下走。

## 16. 2026-10-26 驿站落点：河里 / 栏杆外 / 桥对面

实机截图（2026-10-24 13:27，农场镇）显示驿站亭子立在河道里，玩家站在桥栏杆上，世界标签显示「菜鸭驿站 3 米」，但按交互键没有任何反应，也走不到。日志同一局：

```text
2026-10-24T13:01:24.5048665+08:00 No station point satisfied the 40-80m extraction band for id=farm-central; relaxing
2026-10-24T13:01:24.5068469+08:00 Station placed id=farm-central at 519.4,-2.1,399.5 pass=2
```

锚点是 `512.0,0.061,402.6`，最终落点 `519.4,-2.1,399.5`：水平只挪了 7.7m（第一个 8m 环），垂直掉了 2.16m，`pass=2`。三层原因叠加：

### 16.1 落点判据形同虚设

旧 `SafeGround.Find` 的通过条件是「任意碰撞体 + 坡度 ≤35° + 与 navmesh 高差 ≤1m（找不到 navmesh 时这条整段跳过）+ 0.55m 半径竖直胶囊无遮挡 + `NavMesh.CalculatePath` 完整」。四个漏洞：

- **Water 层碰撞体算地面**：水面本身有碰撞体，`~0` 全掩码照样命中，驿站被吸到水面。
- **`CalculatePath` 会自动把两端投影到最近 navmesh**：从 `anchor` 出发、终点悬空，也照样 `PathComplete`。
- **0.55m 竖直胶囊 vs 3.8×2.9 底座**：只有亭子中心那一根细柱被检查，四角悬空完全查不出来。
- **1m 高差容差**：允许驿站整体沉到路面以下 1m，正好是河道/桥下洼地的深度。

### 16.2 pass=2 放弃全部约束

## 17. 2026-10-27 §16 的修复把驿站全灭：游戏根本没有 navmesh

§16 装进游戏后，日志里**一条新格式的 `Station placed` 都没有**——`ring=` 出现 0 次。三局全部失败，每次都是同一句：

```text
2026-10-26T18:24:16.6009170+08:00 Station pass 0 rejected every point for id=farm-start10: no-navmesh=96
2026-10-26T18:24:16.6272235+08:00 No station point found for Level_Farm_Main; retrying in 10s
```

`no-navmesh=96` 是 6 环 × 16 角 = 96 点全灭，农场镇 10 个锚点、隐藏仓库 10 个锚点无一例外，之后每 10 秒重试一次、连试约 190 次全败。

### 17.1 根因：游戏不用 Unity NavMesh

`TeamSoda.Duckov.Core.dll`（1,806,336 字节）里 `NavMesh` 出现 **0** 次、`NavMeshAgent` **0** 次；游戏用的是 **A\* Pathfinding Project**（`AstarPathfindingProject.dll`，`AstarPath=16`、`Seeker=5`、`RecastGraph=21`、`GridGraph=51`）。`Duckov_Data` 下 201 个资产文件里 `NavMeshData`/`NavMeshSettings`/`NavMeshSurface`/`NavMeshAgent` 全 0 命中，`level10` 里唯一的 `NavMesh` 字符串是 A\* 的 `NavMeshCut` 组件名。游戏自己的 AI 寻路类是 `AI_PathControl`（字段 `Pathfinding.Seeker seeker`、`Pathfinding.Path path`）。

所以 §16 把 `NavMesh.SamplePosition` 从 2.5m 收紧到 1.5m 并当成硬前置条件，等于在一个没有 navmesh 的游戏里一刀切掉所有候选点。**旧版之所以还能放出驿站，是因为 2.5m 采样失败后代码并不 return false、而是继续用射线找地面——那个漏洞反而是唯一能工作的路径。**

### 17.2 修法：判据换成 A\*

1. 新增 `src/CaiYaStation/PathProbe.cs`（`internal static class PathProbe`），封装 A\* 的三个动作：
   - `Ready`：`AstarPath.active != null && !isScanning && data != null && data.graphs.Length > 0`。
   - `TrySnap(point, out snapped, out reason)`：`AstarPath.active.GetNearest(point, NNConstraint.Walkable)`；`ABPath.Construct` 出来的 path 自带 `PathNNConstraint.Walkable`，`GetNearest` 会跳过不可走节点，不必自造约束。`NNInfo.node == null` 记 `no-node`。
   - `TryMeasure(from, to, out length, out reason)`：`ABPath.Construct` → `AstarPath.StartPath(path, false, false)` → `AstarPath.BlockUntilCalculated(path)`。游戏里 `Application.isPlaying == true`，`StartPath` 不会自阻塞，必须自己调 `BlockUntilCalculated`；阻塞返回时 `pathReturnQueue.ReturnPaths(false)` 已跑完，`CompleteState`/`GetTotalLength()` 可直接读。
   - `Release` 只在 `PipelineState >= PathState.Returned` 时才 `Release(active, false)` + `PathPool.Pool`——没走完队列的 path 放回池子会被处理器重复发给下一个调用者。
   - `PlacementBudget = 64` + `ResetBudget()`：每次 `BlockUntilCalculated` 都阻塞主线程，一次全环扫描否则要问几百次；触顶记 `budget-spent`。交互检查（`WithinReach`）传 `budgeted: false`，否则一次落点扫描耗尽预算会让整张地图的驿站全部静默失效。
   - `SnapTolerance = 12f`：recast node 是整个三角形的质心，户外三角形很大，诚实的路面点可能离所属节点十米；**用紧界正是 96/96 全灭的原因**。真正防坏 snap 的是绕行比。
   - `NodeCount()`：供诊断日志用。
2. `SafeGround.Find` / `IsStandable` 的链改为：`TrySnap` → `graph-gap-<米>`（>12m 拒）→ `SampleGround(snapped)` → `PlacementPolicy.GraphAligned(groundY, snapped.y)`（≤0.5m，失败记 `graph-step-<差>`）→ `under-water` → `FootprintFlat` → `occupied` → `TryMeasure` → `detour-<米>m`。`IsStandable` 额外要求存档点自身站在地面上（`|position.y - groundY| ≤ 0.05`，否则 `off-ground-<差>`），否则埋进河床两米的驿站也能过。
3. `StationWorld.TryPlaceStation`：锚点吸附改 `PathProbe.TrySnap`；每个 pass 前 `PathProbe.ResetBudget()`；全部 pass 失败且路径是从锚点算的，就从**玩家实际位置**再算一遍（锚点可能在屋顶/封闭房间，从锚点算出的路径不能证明玩家能到）。
4. `StationWorld.SyncScene`：加寻路图就绪闸门。图没扫完时不动 10 秒重试计时器、直接等下一 tick（每 0.5s 一次）；首次记 `Pathfinder graph not ready for <map>; waiting before placement`，超过 10 秒仍未就绪才弹窗，就绪后记 `Pathfinder graph ready nodes=<N>`。
5. `WithinReach` 的路径段改 `PathProbe.TryMeasure(..., budgeted: false)` + `PathIsReasonable`。
6. `PlacementPolicy.NavMeshAligned` → `GraphAligned`、`MaximumNavMeshGap` → `MaximumGraphGap`（值不变）。
7. `CaiYaStation.csproj` 新增三个引用：`AstarPathfindingProject`、`PackageTools`、`Drawing`。后两个是编译期依赖链——只加 A\* 会报 `CS0012: 类型"VersionedMonoBehaviour"在未引用的程序集中定义`，补 `PackageTools` 后又报 `MonoBehaviourGizmos` 在 `Drawing` 里。
