# 菜鸭驿站 0.1.0 原生接口核对

日期：2026-10-21。对象：本机 `E:\Steam\steamapps\common\Escape from Duckov\Duckov_Data\Managed`，游戏 2.3.30 / build 24013657。方法是只读程序集元数据与 IL 核查，加上 `resources.assets` 只读物品表解析；没有修改游戏文件。

## 1. 送达与领取

| 结论 | 证据 |
| --- | --- |
| `PlayerStorage.Push(Item item, bool toBufferDirectly)` 在 `true` 时直接进到货缓冲区 | IL：`ItemTreeData.FromItem` → `get_IncomingItemBuffer().Add` → `Item.Detach` → `ItemTreeExtensions.DestroyTree` |
| 不需要基地实例 | `get_IncomingItemBuffer` 只调用 `PlayerStorageBuffer.get_Buffer`；后者返回静态 `incomingItemBuffer` |
| 缓冲区列表在类型初始化时创建 | `PlayerStorageBuffer..cctor`：`new List<ItemTreeData>()` → `stsfld incomingItemBuffer` |
| 原生领取为 `PlayerStorage.TakeBufferItem(int)` | 元数据 |

## 2. 支付

| 结论 | 证据 |
| --- | --- |
| `EconomyManager.Pay(Cost, bool accountAvaliable, bool cashAvaliale)` 同时支持账户与现金 | IL：先算 `accountAvailable ? Money : 0` + `cashAvailable ? Cash : 0`，不足返回 false；再从账户扣、再 `ItemUtilities.ConsumeItems(451, 剩余)` |
| `Cost` 可同时含金钱与物品 | 构造 `Cost(long money, (int id,long amount)[] items)` |
| 物品成本由 `ItemUtilities.ConsumeItems(cost)` 扣除 | `Pay` IL |
| 余额查询 | `EconomyManager.Money` / `EconomyManager.Cash`；现金物品 TypeID 451 |

## 3. 玩家背包与物品

| 结论 | 证据 |
| --- | --- |
| 玩家携带容器为 `CharacterMainControl.CharacterItem.Inventory` | `UpdateInventoryCapacity` IL 对 `characterItem.Inventory` 设置容量 |
| 背包内容为 `Inventory.Content` | 元数据；`List<Item>` |
| 物品字段 | `Item.TypeID / DisplayName / Value / StackCount / TotalWeight / Tags / Inventory / CanDrop / Detach` |
| 装备槽判定 | `Item.IsInCharacterSlot()` |
| 销毁整棵树 | `ItemTreeExtensions.DestroyTree(Item)`；`Item.OnDestroy` 会 `Detach`、释放 agent、触发回调 |
| 物品元数据/标签 | `ItemAssetsCollection.GetMetaData(int)` 返回 `ItemMetaData`（含 `tags`、`Name`、`DisplayName`、`priceEach`） |

## 4. 物品 ID 与标签（只读解析 `resources.assets`）

`ItemAssetsCollection` 共 **1569** 条、标签 **134** 个。与设计直接相关的：

| TypeID | 内部名 | 中文名（ChineseSimplified.csv） | 标签 |
| --- | --- | --- | --- |
| 368 | `Feather` | 虚化的羽毛 | `Special` |
| 890 | `BlackDogTag` | 狗牌 | `Special` |
| 451 | `Cash` | 现金 | `Cash`、`NotForSell` |

保护规则使用的实际标签：`Quest`、`Key`、`SpecialKey`、`Cash`、`Continer`（游戏内拼写）、`Backpack`、`Character`。`Equipment` 标签存在，但它表示可装备类别，不代表“已装备”；0.1.0 不用它做硬排除，避免误伤背包里的备用武器/护甲。

任务快递箱名称前缀 `Quest_DeliverBox` 已确认存在（如 `Item_Quest_DeliverBox_2102`），作为名称前缀保护。

## 7. 面板输入拦截

面板是 IMGUI 覆盖层，不会自动阻止游戏输入。0.1.0 使用随包的 Harmony 2.4.1（MIT）与独立 ID `CaiYaStation.PanelInput`，在面板打开时拦截以下入口：

| 类型 | 成员 | 目的 |
| --- | --- | --- |
| `CharacterMainControl` | `Attack`、`StartAction`、`PickupItem`、`UseItem`、`DropAllItems`、`Trigger` | 防止点按钮时开枪/用药/拾取/丢弃 |
| `CharacterMainControl` | `SetAdsInput`、`SetRunInput`、`CanRun`、`CanUseHand` | 防止瞄准/冲刺状态残留 |
| `CharacterMainControl` | `Interact`（两个重载） | 防止面板后再次交互 |
| `InteractableBase` | `StartInteract` | 防止重新进入交互 |
| `ItemAgent_Gun` | `TransToFire`、`ShootOneBullet` | 枪械入口兜底 |

关闭面板、停用模组、UI 异常时都会 `UnpatchAll` 并清空拦截标志。移动不锁定，走远 6 米自动关闭面板。

离线探针只做**目标方法存在性核对**（`Input guard patch targets present (interact overloads=2)`）。Harmony 的 `HarmonySharedState` 在 .NET 10 控制台初始化失败，因此不在探针里真正应用补丁；实际补丁应用需在游戏 Mono 运行时确认。

## 8. 风险

- 上述签名只对当前 build 有效；模组启动时 `NativeContract` 会逐项检查，失败则停用功能并列出缺失项，不会带病发货。Harmony 输入拦截单独降级：补丁目标缺失时只记录日志并关闭拦截，不影响寄送主流程。
- `PlayerStorage.Push` 对堆叠/容器/任务物品的实际表现仍需实机 spike；0.1.0 已排除容器，并在推送前重新读取背包。
- `Cost` 的物品消耗会搜索玩家所有库存（含仓库/宠物），0.1.0 用“背包内数量足够”做前置条件，保证不会出现没随身携带也能请护送。
